# FXLinker 利用マニュアル (v2.0)

**FXLinker** は、MikuMikuDayo上で「カスタムポストエフェクト」を作成・適用するためのフレームワークです。
MMEと同様にUI上からエフェクトを適用する材質を選択できます。
HLSLコード片（`.fxsrc`）を書くと、自動的にUIへの登録、シェーダー生成、パラメータ制御用PMXの生成を行います。

## 1. 概要
FXLinkerを使用すると以下の手順でポストエフェクトを適用できます。

1.  **書く**: `UserEffects` フォルダに `.fxsrc` ファイルを作成。
2.  **待つ**: MikuMikuDayo起動時（またはリロード時）に自動的に変換されます。
3.  **使う**: UIの「Effect Mapping」から材質ごとにON/OFFしたり、自動生成されたPMXのモーフでパラメータを調整したりできます。


Compute Shader (CS) は連鎖（カスケード）させることが可能です。これにより「マスク生成」→「ブラー(横)」→「ブラー(縦)」といった画像処理を行った後、最後に Pixel Shader (PS) で合成するパイプラインなどを定義できます。

## 2. パイプライン構造
FXLinkerのエフェクトは、**「任意の回数の CS パス」** と、**「最後の 1回の PS パス」** で構成されます。

### 処理の流れ（例：ブラー付きエフェクト）
データの受け渡しには、システムが管理する中間バッファ（`WorkTex` 等）を使用します。

1.  **Pass 0 (CS):** 材質ID等を見てマスク生成 → `WorkTex` へ書き込み
2.  **Pass 1 (CS):** `WorkTex` を横にぼかす → `TempTex` へ書き込み
3.  **Pass 2 (CS):** `TempTex` を縦にぼかす → `WorkTex` へ書き戻し (カスケード完了)
4.  **Pass 3 (PS):** 最終的な `WorkTex` と元の画面を合成 → **画面に出力**

※ **FXLinker**ではリムライトなどの材質単位で適用したいエフェクトでの利用を想定しており、必要な項目をシンプルに記載することに特化したフォーマットになっています。よって、`fxdayo`エフェクトフレームワークのすべての機能を使用できるわけではありません。

## 3. ソースコードの書き方 (.fxsrc)

ファイルの拡張子を `.fxsrc` にして保存してください。
標準的なHLSL構文に加え、**アノテーション（注釈）** を用いてパイプラインを定義します。

### 3.1 アノテーションによる定義
行頭に `// @キーワード: パラメータ` を記述することで、エフェクトの構成を定義します。

| アノテーション | 書式 | 説明 |
| :--- | :--- | :--- |
| **@pass** | `@pass: [PassName] ([Type])` | 新しいパスの開始を宣言します。<br>**Type**: `CS` (計算) または `PS` (描画) |
| **@read** | `@read: [TextureName]` | 前のパスの結果を読み込む(SRV)ことを宣言します。 |
| **@write** | `@write: [TextureName]` | 結果を書き込む(UAV)ことを宣言します。<br>**※CSでのみ使用可能です** |
| **@morph** | `@morph: [MorphName] = [VarName]` | PMXモーフと変数を紐づけます。 |

### 3.2 記述ルール
* **順序**: 上から定義された順に実行されます。`CS` パスを好きなように記述し、ファイルの最後に `PS` パスを1つ記述してください。
* **#ifdef ガード**: 各パスの関数は `#ifdef YRZ_PASS_[PassName]` ～ `#endif` で囲む必要があります。
* **リソース定義不要**: `@read`, `@write` で指定したテクスチャ変数は、システム(FXLinkerおよびfxdayoエフェクトフレームワーク)が自動的に定義・バインドします。

### 3.3 Compute Shader (CS) の書き方
`@write` で指定したテクスチャ（`WorkTex`, `TempTex` 等）に値を書き込みます。
スレッドサイズは `(16, 16, 1)` 固定です。

**関数シグネチャ:** `void 関数名(int2 pos)`

```hlsl
// --------------------------------------------------------
// Pass 0: MaskGen (CS)
// --------------------------------------------------------
// @pass: MaskGen (CS)
// @write: WorkTex
#ifdef YRZ_PASS_MaskGen
void CS_MaskGen(int2 pos)
{
    // WorkTexは自動定義されているのでそのまま使える
    // 初期化（重要：CSは全ピクセルを埋めない場合、前の値が残るため）
    WorkTex[pos] = float4(0, 0, 0, 0);

    // G-Buffer情報の取得
    uint2 gb = GBuffer1[pos];
    if (gb.r != Inai) {
        // ... (判定ロジック) ...
        WorkTex[pos] = float4(1, 0, 0, 1);
    }
}
#endif
```

### 3.4 Pixel Shader (PS) の書き方
パイプラインの最後に行う合成処理です。`@read` したテクスチャと現在の画面を合成して返します。
**このパスでのみ、最終的な色が画面に反映されます。**

**関数シグネチャ:** `float4 関数名(VSO vso)`
※戻り値のセマンティクス `: SV_Target` は記述不要です。

```hlsl
// --------------------------------------------------------
// Pass Final: Composite (PS)
// --------------------------------------------------------
// @pass: Composite (PS)
// @read: WorkTex
#ifdef YRZ_PASS_Composite
float4 PS_Composite(VSO vso)
{
    // 現在の画面色を取得
    float4 col = ScreenTexture.Sample(ClampSamp, vso.uv);
    
    // 前のパスの結果をサンプリング
    float4 mask = WorkTex.Sample(ClampSamp, vso.uv);

    // 加算合成
    return col + mask;
}
#endif
```

## 4. コントローラ（パラメータ調整）
シェーダー内の変数を、自動生成されるPMXモデル（`UserEffects/AutoGenerated/エフェクト名.pmx`）のモーフで操作できます。

### 4.1 標準コントローラ
以下の変数は、宣言なしでシェーダー内で使用可能です。

| 変数名 (HLSL) | 対応モーフ名 | 用途例 |
| :--- | :--- | :--- |
| `X`, `Y`, `Z` | X, Y, Z | 位置、座標制御 |
| `Rx`, `Ry`, `Rz` | Rx, Ry, Rz | 回転、カラー制御(RGB) |
| `Si` | Si | サイズ (Size) |
| `Tr` | Tr | 透明度 (Transparency) / 強度 |

### 4.2 カスタムコントローラ
任意の変数をモーフに紐づけられます。

```hlsl
// @morph: リム強度 = RimPower
// @morph: リム色 = RimColor
```
これで `uniform float RimPower;` 等がシェーダー内で使えるようになり、「リム強度」モーフで操作できます。

## 5. システムリソース一覧
シェーダー内でいつでも参照可能なリソースです。

| リソース名 | 型 | 内容 |
| :--- | :--- | :--- |
| `ScreenTexture` | `Texture2D<float4>` | 現在の画面の色 |
| `GBuffer1` | `Texture2D<uint2>` | `.r`: モデルID (背景は `Inai`)<br>`.g`: 面ID |
| `GBuffer2` | `Texture2D<float2>` | 重心座標 |
| `NormalDepth` | `Texture2D<float4>` | `.rgb`: 法線<br>`.a`: リニア深度 |
| `Resolution` | `float2` | 画面解像度 (x:幅, y:高さ) |
| `MaterialEffectBits` | `StructuredBuffer` | 材質ごとのエフェクトON/OFFフラグ |
| `Faces` | `StructuredBuffer` | 面IDから材質IDへの変換テーブル |
| `MY_BIT_FLAG` | `uint` | 自身のFXLinkerエフェクトを示すビットフラグ |

UIから指定されている材質のみを対象とする場合、以下のようなコードになります。

```hlsl
    uint2 gb = GBuffer1[pos];
    // 背景(Inai)以外なら計算
    if (gb.r != Inai) {
        // 対象の材質かチェック (Generatorが生成したフラグ判定)
        uint matID = Faces[NonUniformResourceIndex(gb.r)][gb.g];
        uint bits = MaterialEffectBits[NonUniformResourceIndex(gb.r)][matID];
        
        if (bits & MY_BIT_FLAG) {
             /* 対象の材質で、自身のエフェクトがONになっていれば、分岐内が実行される */
        }
    }
```

## 6. 注意事項
* **WorkTexの初期化**: CS内で `WorkTex[pos]` への書き込みを行わないピクセルは値が不定になるため、必ず `float4(0,0,0,0)` 等で初期化を行ってください。
* **G-Bufferアクセス**: `GBuffer1` へのアクセスは `int2` のピクセル座標を使用してください。
    * PS内では `int2 pos = int2(vso.position.xy);` で取得可能です。
* **中間バッファ**: `WorkTex` 以外にも、CSパスの `@write` に `TempTex` のように任意の名前を書けば、システムが自動的に一時バッファを作成・確保します。
